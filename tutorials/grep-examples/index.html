Linux grep Examples: Search Text, Logs and Files

Learn grep with practical Linux examples for line numbers, case-insensitive searches, regular expressions, recursive search, and exit status.

What does grep do?

grep searches input for lines matching a pattern. Basic regular expressions are the default on common GNU and BusyBox versions; flags and extended features can differ by implementation.

Useful grep examples

grep 'error' app.log
grep -n 'error' app.log
grep -i 'warning' app.log
grep -r 'TODO' ./src
grep -E 'error|failed' app.log
grep -v '^#' settings.conf
  • -n prints line numbers.
  • -i ignores case when matching.
  • -r searches directories recursively; be careful with large or sensitive trees.
  • -E enables extended regular expressions on standard implementations.
  • -v selects non-matching lines.

Use quoting and patterns deliberately

Single quotes usually keep the shell from expanding characters in a pattern. For example, grep '^[[:space:]]*#' settings.conf finds lines whose first non-whitespace character is a comment marker. This is a regular expression, not a literal search.

Search files without changing them

grep -n 'TODO' ./src/*.c
grep -R --include='*.log' 'timeout' ./logs

Search commands read files but can reveal secrets if output is copied into logs or shared. Avoid searching or publishing credentials, tokens, private keys, and personal data. Check your implementation's man grep for supported flags.

When grep finds nothing

No matching lines normally means grep exits with status 1; errors such as unreadable files can produce a different nonzero status. In shell scripts, handle exit status intentionally rather than treating every nonzero result as the same failure.
