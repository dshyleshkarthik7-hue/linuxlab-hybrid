How to troubleshoot safely

  1. Read the whole message. Note the command, path, hostname, and exact error text.
  2. Observe before changing. Use pwd, ls -l, df -h, or ss -ltn when relevant to gather evidence.
  3. Make one small change at a time. Avoid broad sudo, recursive permission changes, or deleting locks while a process may still be active.
  4. Verify the result. Rerun the original operation and compare the output.

This is a curated troubleshooting reference, not a guarantee that one diagnosis fits every distribution. If the message is not recognized, search the exact wording in the official documentation for the command and your distribution.
