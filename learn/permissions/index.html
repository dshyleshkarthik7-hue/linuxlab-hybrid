Understand Linux permissions

Linux permissions control who can read, write or execute a file. Understanding them is essential for administration and a foundation for security work.

Read the rwx model

ls -l script.sh
-rwxr-x--- 1 user developers 1200 script.sh

The permission triplets describe owner, group, and others. r means read, w write, and x execute.

SymbolMeaning for a regular file
rRead contents
wModify contents
xExecute as a program

Understand numeric modes

Numeric modes add the permission values for owner, group and others. Read is 4, write is 2, and execute is 1. For example, 640 means owner read/write (6), group read (4), and others no permissions (0). This describes ordinary permission bits; directory permissions have different practical effects because execute controls traversal.

ModeMeaningTypical context
600Owner read/write onlyPrivate files that should not be shared
640Owner read/write, group readGroup-readable configuration or notes
750Owner full, group read/executeShared executable or directory with restricted access
755Owner full, others read/executePublicly readable program or directory where appropriate

These are examples, not universal defaults. The correct mode depends on the file, its contents, the owner/group and the application.

Change permissions deliberately

chmod u+x script.sh
chmod g-w shared.txt
ls -l script.sh shared.txt

Symbolic mode is readable: u is owner, g group, and o others. Prefer the smallest permission change that accomplishes the task.

Security principle: Least privilege means granting only the access that is actually required. Avoid making files broadly writable or executable just to “make it work.” Never use chmod -R on a broad path without first checking the target and understanding the recursive effect.

Check ownership separately

Permissions and ownership answer different questions. ls -l shows the owner and group; chown changes ownership where you have sufficient privilege. Changing ownership is not the same as changing rwx bits, and recursive ownership changes should be scoped narrowly.

Quick questions

Does chmod 777 fix every permission error?

No. It grants broad read, write and execute permissions and may create avoidable risk. Diagnose the path, owner, group and required operation first.

Are file and directory permissions identical in effect?

No. On directories, read controls listing names, write affects creating/removing entries, and execute allows traversal subject to other access controls.
