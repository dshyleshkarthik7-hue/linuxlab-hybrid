Learn Linux networking fundamentals

Understand the path from a network interface to an application: address, route, name resolution, transport connection and application protocol. The browser Linux lab intentionally disables guest networking, so these lessons teach the concepts without requiring network access.

The five questions

QuestionConceptTypical Linux observation
Which interface exists?Link/interfaceip link
What address is assigned?IP addressingip addr
Where does traffic go?Routingip route
What name maps to an address?DNS/name resolutiongetent hosts example.com
Which application endpoint responds?Ports/protocolsss -lnt or ss -lntp
Debugging habit: Work from the lower layer upward. An application cannot be healthy if the required interface, route or name resolution is already broken.

IP addresses and routes

ip link
ip addr
ip route

An interface is a network attachment. An IP address identifies an endpoint on a network. A route tells the kernel where packets for a destination should be sent. A default route is the fallback for destinations without a more specific route.

Do not assume a particular interface name such as eth0; modern Linux systems commonly use predictable names and virtual environments may expose different devices.

DNS, TCP and HTTP

DNS answers a naming question. TCP provides a reliable byte stream between endpoints. HTTP defines how web clients and servers exchange application messages. These are different layers and can fail independently.

getent hosts example.com
curl -I https://example.com

On LinuxTerminal's real browser guest, networking is disabled by design. Use the simulator for conceptual command practice and use an ordinary Linux system you control when a lesson requires live network traffic.

Safety boundary: These exercises are for systems and networks you are authorized to use. Prefer observation and documentation over probing systems you do not control.

Practice loop

  1. State the exact networking question you want to answer.
  2. Choose the lowest-level observation that can answer it.
  3. Change one variable at a time.
  4. Record the evidence and distinguish “not observed” from “does not exist.”
