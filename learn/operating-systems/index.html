Understand the Linux operating system

Move from memorizing commands to understanding the system they control. The kernel, processes, filesystems, devices, users, services and packages form a set of cooperating layers.

Build the mental model

LayerQuestion to askUseful observation
KernelWho manages CPU, memory and devices?uname -a
ProcessesWhich programs are running?ps
FilesystemWhere is data organized?pwd, ls, df
UsersWho owns or can access something?id, ls -l
PackagesHow is software installed and updated?Use your distribution's package manager
Key idea: A command is usually an interface to one layer. When troubleshooting, identify the layer first instead of trying random commands.

Boot, init and services

Boot begins with firmware and a bootloader, then the kernel starts and hands control to an init system or another userspace entry point. On many Linux distributions, a service manager starts long-running services and tracks their state.

uname -a
ps
cat /proc/1/comm
cat /etc/os-release

These commands are observations, not universal assumptions: PID 1, the init implementation and available files differ between distributions and containers.

Practice safely: Observe services before changing them. On a real machine, stopping a service can interrupt other users or applications.

Filesystems are more than folders

Linux presents devices, pseudo-filesystems and ordinary storage through a common filesystem interface. /proc exposes kernel and process information, while /sys exposes hardware and kernel state. They are not ordinary folders of permanent files.

findmnt
df -h
ls /proc | head
ls /sys | head

In the browser lab, available mounts and files depend on the selected guest image. Use the output you actually observe as evidence.

Practice loop

  1. Predict what layer a command will inspect.
  2. Run one small observation.
  3. Compare stdout, stderr and exit status with your prediction.
  4. Explain what the evidence proves and what it does not prove.
