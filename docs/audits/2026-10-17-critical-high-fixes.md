# Release follow-up fixes — 17 October 2026

This follow-up applies the actionable code and UX items from the release audit. Changes are committed directly to `main`.

## Implemented

- Careers feed contract now matches the safe DOM helper used by the client; tests cover list/listitem semantics, polite status announcements, busy-state reset, stale-list clearing, descriptive job links, and absence of `innerHTML`.
- Careers client clears stale content before rendering and after errors, removes the error class after a successful response, and uses accessible list and status roles.
- Developer Alpine copy no longer claims the image is already verified. It explains pinned source integrity and the limits of whole-image verification, adds a Quick Linux recovery link, and recommends the lighter profile on devices reporting low memory or CPU capacity.
- Progress supports local JSON export/import. Import has a 1 MiB limit, strict schema checks, bounded record lists, field normalization, score validation, and a confirmation before replacing the local ledger. Snapshot round-trip and malformed/malicious JSON contract tests run in CI.
- Expanded progress badges to eight named achievements across Bronze, Silver, Gold and Platinum tiers, added next-badge progress, a local SVG badge-card export, and an unlock animation that is disabled when reduced motion is preferred.
- Challenge cards distinguish curated tasks from catalog entries with limited lesson detail. The filter result count is a polite live region and cards have visible keyboard focus.
- Accessibility smoke checks now verify first-stop skip-link behavior and visible focus, plus challenge result announcements and progress backup controls.
- Added an optional dismissible homepage onboarding path: Learn → Commands → Challenges → Progress.
- Kept Node 22, LFS hydration/preflight, and the existing CI contracts; added the progress snapshot contract to both the main test suite and CI test gate.
- Split the progress controller into readable functions while preserving the browser-local progress model.
- Strengthened the careers external-source disclaimer.

## Intentionally not claimed as complete

- This ZIP/repository view does not provide production secrets or prove live Netlify/Cloudflare behavior. Run `npm run release:preflight` in the staging environment with approved credentials, then run the production smoke workflow only with explicit release approval.
- The real Developer Alpine ISO and generated per-chunk manifest must be hydrated/generated by the LFS/release workflow. Do not claim successful VM boot or full artifact verification based only on source contracts.
- The full Playwright/browser matrix, cross-browser accessibility review, and live Tutor provider revision check must pass in CI/staging.
- Ads remain absent. AdSense should not be enabled without a publisher ID, a compliant consent-management setup, and an independently reviewed CSP/placement plan.
- A second trusted maintainer must still be added by the repository owner and CODEOWNERS review enabled in the active GitHub ruleset.
